# 任务与提示词适配规则

前台输入按具体任务定义，不把通用六项字段强加给所有任务。场景用于查找，taskType 用于描述主要动作；同一类型仍需按业务规则细化。

|任务|逻辑|参考组织方法|
|---|---|---|
|business-report-ppt-outline|目标与受众 → 材料与主线 → 逐页表达 → 交付核验|受众表达 + 分页规划（CO-STAR / RISE 思路）|
|customer-review-analysis|样本界定 → 分类编码 → 统计汇总 → 优先跟进|输入分类 + 统计复核（ICIO）|
|excel-multi-sheet-merge|源表盘点 → 合并分支 → 映射处理 → 对账交付|输入转换 + 条件分支（ICIO / RISEN）|
|excel-sales-analysis|业务问题 → 数据审查 → 指标口径 → 计算比较 → 证据建议|口径确认 + 计算核验（ICIO / RISEN）|
|meeting-notes-action-items|记录校对 → 发言状态识别 → 决策与行动提取 → 来源复核|证据提取 + 状态区分（ICIO）|
|xiaohongshu-topic-planning|定位与目标 → 场景需求 → 单篇交付 → 素材匹配 → 去重排序|受众目标 + 选题探索 + 筛选（CO-STAR / CRISPE 思路）|

框架名称仅作为编写参考，不作为效果保证或前台必学概念。默认明确输入、处理规则、输出及验收；关键规则缺失才等待确认，局部未知可标记继续。不得要求展示内部思维过程。

案例提示词与用户填写提示词均从同一 solutionContent 生成，避免两套规则漂移。新增任务必须说明业务单位、分支、缺口处理、结果结构和可核验标准。当前完成内容与渲染检查，尚不等于外部模型执行测试通过。

## 框架模块实现
框架定义集中在 data/prompt-frameworks.ts。表单分组与案例说明读取同一份模块配置，正文使用相同字母、中英文名称。CO-STAR 使用 C/O/S/T/A/R，TRACE 使用 T/R/A/C/E，RISEN 使用 R/I/S/E/N，RTF 使用 R/T/F，CRISPE 使用 C/R、I、S、P、E。当前任务只启用适配框架；APE、RACE、BROKE、CREATE 留待对应任务加入，不强行套用。角色和固定执行规则预置，选填模块有默认行为。

演示与汇报现有三个独立任务：PPT 策划与演讲稿采用 CO-STAR，汇报内容组织采用 RACE。分别交付逐页策划、口语稿和证据型简报，均有示例材料与结果。新增 RACE 定义固定为 Role、Action、Context、Expectation。尚未完成外部模型效果实测。

复制输出格式统一为任务指令、任务信息与材料、交付要求、执行要求、验收标准。框架名称与字母保留在说明层，不作为复制文本中的表单标签。输入原文仅做安全替换，不做语义判断和自动改写；模板空行在替换前归一化，保留用户原文换行。

默认交付与缺口处理已统一：可推荐的格式、步骤和部分专业配置改为选填，并在正文给出默认规格。关键业务事实、统计或关联口径仍需确认；局部缺失标记后继续；仅提到附件而未收到时提醒。复制前仅做结构校验，错误只在字段下显示。PPT 不再要求固定标签。

## 分支与边界组装
多表合并通过 promptVariants 按 mode 选择纵向追加、横向关联、仅检查建议三个模板，详情复制与案例预览共用 selectPrompt；追加省略 join_key，不读取保留的旧值。分支模板纳入 schema、占位符语义校验与关键内容变更检查。用户要求优先于补充规格，事实真实性和工具能力限制始终保留。八个任务明确交付范围、无材料及替代交付状态。

输出模板收敛为任务说明、输入材料、输出要求、处理规则。outputDefault 仅用于选填为空时的复制输出，不预填表单、不覆盖用户原文，也不使条件必填跳过校验。模板默认和用户值二选一；多表合并仍按分支输出。验收要点融入处理规则，页面验收说明继续保留。
