# 31 场景提示词重构

## 内容职责

`data/prompt-blueprints.json` 保存正式提示词的任务开场、按框架组织的模块、独立段落和交付分支；运行时由 `lib/prompt-blueprint.ts` 编译。用户填写内容由 `lib/template.ts` 单次替换，不修改用户表达、不解释用户输入中的占位符。

`Variable.label` 仅用于表单问题，`promptLabel` 用于正式指令。表单按 `prompt-frameworks.ts` 的模块及字段顺序呈现。框架不是展示标签：目标、材料、动作、交付必须映射到其对应模块。

## 本次校正

- 23个新增场景重新编写模块正文，去掉案例数量、来源编号、具体结论及重复执行规则。
- 原有8个场景保留专业业务逻辑；合并重组处理方式、执行步骤和保护边界；评价交付变量归入要求模块；历史选题归入洞察模块。
- COAST分别填写任务和目标；ROSES区分目标和需求情境；BROKE独立填写可检查关键结果。
- 所有31个场景及分支统一检查正式标签、句末标点、字段覆盖和案例可填充性。

## 新增与维护

先定义任务、使用者、材料和交付，再选择框架；给每个字段绑定唯一模块。按模块编写完整指令，不从表单问题生成提示词。先写通用模板，再为案例填写变量；案例事实不能硬编码在通用执行规则中。运行 `npm run validate-content`、`npm test`，并核对案例交付与材料。

参考案例用于说明交付形式。结构测试不代表外部AI输出效果已验证，所有内容保留草稿状态。
